# Describe the implemented project

Treat the repository name, About description, topics, homepage and README introduction as one consistent promise. Name the actual deliverable and audience instead of using a list of fashionable technologies. A catalogue that expands from AI models into procedural simulation should update its discovery metadata alongside its documentation.

Choose topics that a likely user would recognise and that the current contents support. Link a working homepage when one exists; otherwise link the documentation or leave the field unset. Do not create a fake demo URL solely to satisfy a checklist. A screenshot, social preview or logo is helpful only when it clarifies the project.

Review discovery text after a scope change or major release. Compare it with the code, examples and supported environments, not just the roadmap. Avoid star exchanges, irrelevant keywords, visitor-counter badges and claims of guaranteed search placement.

The offline auditor cannot see GitHub About fields. Its corresponding findings remain unknown unless a dated observation is supplied. A topic-presence observation says that topics exist, not that those topics are relevant. Relevance remains an editorial judgement.
